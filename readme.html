web-crud

Aplicación web sencilla para que un negocio pequeño lleve su inventario y sus pedidos desde la red local, con columnas que el propio cliente puede agregar, como lo haría en Excel.

  • Django
  • Gunicorn
  • Nginx
  • SQLite
  • Servidor en el local del cliente
  • Docker (Windows)

Qué hace

  • Inventario: alta, consulta, edición y baja de productos.
  • Pedidos: registro de pedidos con sus productos y cantidades.
  • Columnas personalizadas: el cliente agrega sus propios campos a los datos sin tocar código.
  • Acceso con login: solo entran usuarios autorizados, con sesión que expira.

Arquitectura

Todo corre en una sola máquina dentro del negocio. El navegador de cualquier equipo de la red local llega a Nginx, que atiende HTTPS y reenvía las peticiones a Gunicorn, y este ejecuta la aplicación Django. Los datos viven en un archivo SQLite dentro de data/.

Por qué estas piezas

  • Nginx termina HTTPS, agrega headers de seguridad y entrega los archivos estáticos.
  • Gunicorn ejecuta Django con varios procesos; Django no está pensado para exponerse solo.
  • Django aporta login, sesiones, protección CSRF y un ORM que evita armar SQL a mano.
  • SQLite basta para un negocio con poca carga y no requiere instalar otro servicio.

Seguridad

Cada medida corresponde a una lista de seguridad del tablero de Trello.

ÁreaMedida
Login y hashingContraseñas con Argon2 o PBKDF2 de Django; bloqueo temporal tras varios intentos fallidos.
SesionesCookies Secure y HttpOnly, con expiración.
Validación de inputsValidación en el servidor, con atención especial a los nombres y valores de las columnas personalizadas.
SQL injectionSolo consultas por ORM, sin SQL armado con texto del usuario.
XSSAutoescape de plantillas activo; sin |safe sobre datos del usuario.
CSRFToken CSRF en todos los formularios que modifican datos.
ConfiguraciónDEBUG=False, SECRET_KEY fuera del repositorio y ALLOWED_HOSTS definido.
TransporteHTTPS en la red local con certificado autofirmado y headers de seguridad en Nginx.

Se está considerando un agente de IA que pruebe estas protecciones de forma automática.

Despliegue

  • En el local del cliente: una PC o mini servidor dentro de la red del negocio. No usa VPS, así que no depende de que el proveedor de internet abra puertos.
  • Linux: deploy.sh prepara el entorno, Gunicorn corre como servicio de systemd y Nginx hace de proxy.
  • Windows: la aplicación se empaqueta con Docker para correr igual en ambos sistemas.

La base de datos SQLite está en data/. Esa carpeta es la que hay que respaldar.
